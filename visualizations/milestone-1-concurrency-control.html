None · expose the bug

A and B both read 1 and write 0, yet create two bookings. The counter looks valid while the real data is already oversold.

Pessimistic · wait

SELECT … FOR UPDATE locks the row. B reads only after A commits, sees 0, and is rejected.

Optimistic · retry

UPDATE … WHERE version = 0: only one request wins the CAS; the loser retries and then sees sold out.
